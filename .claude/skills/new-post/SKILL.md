# New-Post Skill — BlogStudio

You are scaffolding a new blog post directory. Creates `01_POSTS/YYYY-MM-DD-<slug>/` with `body.md` and per-target frontmatter files (`<adapter>.md`) for the user's default adapters.

## When to use

- A user says "/new-post", "scaffold a new post", "let me start writing", or similar.

## Detect defaults

Read `.claude/.bootstrap-defaults.json` (created by `/bootstrap`) for:

- `adapters` — which per-target frontmatter files to create
- `baseUrl` — for `canonical_url` defaults
- `authors` — default author byline

If `.bootstrap-defaults.json` doesn't exist, ask the user the same questions inline (or suggest they run `/bootstrap` first).

## Interview

### 1. Post title

> "What's the title?"

Title becomes the `title:` frontmatter field. Slug derived from the title (lowercase, hyphens for spaces, strip non-alphanumeric) — but ask the user to confirm or override the slug.

### 2. Slug confirmation

> "Slug derived as `<auto-generated>`. Use it, or override?"

The directory will be `01_POSTS/<today's-date>-<slug>/`.

### 3. Tags / description (optional, can skip)

> "Tags? (comma-separated, or skip)"
> "One-line description for SEO and post-list previews? (or skip)"

### 4. Series? (optional)

> "Is this part of a series? (slug or skip)"

If yes, ask for `series_order`. The post goes in `01_POSTS/<series-slug>/<NN>-<slug>/` instead of the date-prefixed top-level path.

### 5. Adapters (skip if defaults exist)

If `.bootstrap-defaults.json` exists, use the captured adapters silently. Otherwise:

> "Which target adapters? (markdown, hugo, ghost, substack, jekyll — pick any)"

## Scaffold

Create the directory + files:

```text
01_POSTS/<date>-<slug>/   (or 01_POSTS/<series>/<NN>-<slug>/ for series)
├── body.md           ← scaffold with H1 (title) and a placeholder paragraph
├── markdown.md       ← if adapter selected
├── hugo.md           ← if adapter selected
├── ghost.md          ← if adapter selected
├── substack.md       ← if adapter selected
└── jekyll.md         ← if adapter selected
```

### body.md scaffold

```markdown
# <Title>

<!-- Write the post here. The title H1 is repeated from frontmatter for editing convenience;
     adapters that own their title rendering may strip it. -->

Earned hook in the first three sentences. The reader should know exactly why this post exists by sentence three.

## First section

Body content here.

## Conclusion

Sharp wrap. No "in conclusion" phrases.
```

### Per-target frontmatter scaffolds

Each `<adapter>.md` gets the appropriate frontmatter for that adapter (validated against the per-target schema) plus:

```markdown
{{ include "body.md" }}
```

For example, `hugo.md`:

```markdown
---
title: "<Title>"
date: <YYYY-MM-DD>
authors: <from defaults>
tags: [<from interview>]
description: "<from interview>"
draft: false
---

{{ include "body.md" }}
```

For series posts, also include `series:` and `series_order:` in the frontmatter.

## After scaffold

```text
New post scaffolded:
  - 01_POSTS/2026-04-25-my-post/
    ├── body.md
    ├── markdown.md
    └── hugo.md

Next:
  - Open body.md and write
  - npm run build to compile when ready
```

## Validation

Before claiming done, confirm the scaffolded `<adapter>.md` files validate against their per-target schemas (`npm run validate` should pass).
